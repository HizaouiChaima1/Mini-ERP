Exemple : Vérifier la disponibilité d'un produit\n\n`java\n@Service\npublic class OrderService {\n    \n    private final StockServiceRmi stockServiceRmi;\n    \n    @Autowired(required = false)\n    public OrderService(StockServiceRmi stockServiceRmi) {\n        this.stockServiceRmi = stockServiceRmi;\n    }\n    \n    public void createOrder(Long productId, Integer quantity) {\n        try {\n            // Appel RMI synchrone au service Stock\n            Boolean available = stockServiceRmi.isProductAvailable(productId, quantity);\n            \n            if (available) {\n                // Réserver le produit\n                stockServiceRmi.reserveProduct(productId, quantity);\n                \n                // Créer la commande...\n            }\n        } catch (RemoteException e) {\n            log.error(\"Service Stock indisponible\", e);\n            throw new OrderException(\"Impossible de vérifier le stock\");\n        }\n    }\n}\n`\n\n### Service de communication RMI (Pattern recommandé)\n\nChaque service a une classe `RmiCommunicationService` qui centralise les appels RMI :\n\n`java\n@Service\npublic class RmiCommunicationService {\n    \n    private final StockServiceRmi stockServiceRmi;\n    \n    @Autowired(required = false)\n    public RmiCommunicationService(StockServiceRmi stockServiceRmi) {\n        this.stockServiceRmi = stockServiceRmi;\n    }\n    \n    public Integer getProductQuantity(Long productId) {\n        try {\n            if (stockServiceRmi != null) {\n                return stockServiceRmi.getProductQuantity(productId);\n            }\n        } catch (RemoteException e) {\n            log.error(\"Erreur RMI\", e);\n        }\n        return 0;\n    }\n}\n`\n\n---\n\n## 🔄 Architecture de communication\n\n`\nFrontend found\"\n\n**Cause** : Le service RMI n'est pas accessible\n\n**Solutions** :\n1. Vérifier que le service est démarré : `docker ps`\n2. Vérifier le port : `netstat -an | grep 1099`\n3. Consulter les logs : `docker logs stock-service`\n4. Vérifier la configuration Docker Compose\n\n### Proxy RMI non injecté (null)\n\n**Cause** : Connexion au service distant non établie\n\n**Solution** :\n`java\n@Autowired(required = false)  // Important!\npublic MyService(StockServiceRmi stockServiceRmi) {\n    this.stockServiceRmi = stockServiceRmi;\n}\n\n// Vérifier avant utilisation\nif (stockServiceRmi != null) {\n    // Utiliser le proxy\n}\n`\n\n### \"Port already in use\"\n\n**Cause** : Un autre processus utilise le port RMI\n\n**Solution** :\n`bash\n# Trouver le processus\nlsof -i :1099\n\n# Arrêter le processus\nkill -9 <PID>\n`\n\n---\n\n## 📊 Comparaison REST vs RabbitMQ vs RMI\n\n| Aspect | REST | RabbitMQ | RMI |\n|--------|------|----------|-----|\n| **Communication** | Synchrone | Asynchrone | Synchrone |\n| **Typage** | JSON (Weak) | Pas de typage | Java (Fort) |\n| **Performance** | Modérée | Haute (async) | **Haute** |\n| **Couplage** | Lâche | Très lâche | **Fort** |\n| **Latence** | Élevée | N/A | **Très basse** |\n| **Scalabilité** | Bonne | Excellente | Modérée |\n| **Fiabilité** | Modérée | Excellente | Modérée |\n| **Complexité** | Faible | Modérée | Modérée |\n\n**Recommandation** : Utiliser RMI pour les appels synchrones inter-services fortement typés, RabbitMQ pour l'asynchrone, et REST pour l'API externe.\n\n---\n\n## ✅ Checklist d'intégration\n\n- [x] Module `rmi-common`
